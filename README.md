## What Is This?

Local RAG Assistant is a Retrieval-Augmented Generation (RAG) pipeline that runs entirely inside your browser. It allows you to:

- Upload documents (PDF, Word, plain text, or images)
- Have those documents automatically parsed, chunked, and vectorised
- Ask natural-language questions about the content
- Receive accurate, cited answers generated by a locally running Large Language Model (LLM)

No data is ever sent to a cloud server. Everything — parsing, embedding, vector search, and LLM inference — happens on your own machine.

## How It Works

The RAG pipeline follows four distinct stages:

### Stage 1 — Document Parsing

When a file is uploaded, the application selects the appropriate parser:

- **PDF** → pdf.js extracts text page by page
- **DOCX** → mammoth.js strips the Word XML and returns raw text
- **TXT** → native browser File API reads the content directly
- **Images** → Tesseract.js runs Optical Character Recognition (OCR) locally

### Stage 2 — Chunking

The extracted text is split into overlapping chunks of approximately 500 words, with an 80-word overlap between consecutive chunks. Overlap ensures that information spanning a chunk boundary is not lost during retrieval.

### Stage 3 — Embedding

Each chunk is sent to Ollama's local API endpoint (`/api/embeddings`) using the `nomic-embed-text` model. This model converts the chunk into a dense numerical vector that encodes its semantic meaning. These vectors are stored in memory alongside the original chunk text and its source document name.

### Stage 4 — Query & Generation

When a question is submitted:

1. The question is embedded into the same vector space using `nomic-embed-text`
2. Cosine similarity is computed between the query vector and every stored chunk vector
3. The top-K most similar chunks are selected
4. Those chunks are injected into a system prompt as context
5. The full prompt is sent to Ollama's chat API (`/api/chat`) with streaming enabled
6. The LLM generates an answer grounded strictly in the retrieved context
7. Source document names are displayed as citation chips below each answer

## Why It Works Without a Backend

Traditional RAG systems require a backend server, a vector database, and a cloud LLM API. This application eliminates all three:

- **Embedding generation** — Ollama exposes a local HTTP API at `http://localhost:11434`. The browser calls this directly using the native Fetch API.
- **Vector storage** — Embeddings are stored as plain JavaScript arrays in memory. Cosine similarity search runs in pure JavaScript — no external database needed.
- **LLM inference** — Ollama handles model inference locally. The browser streams the response using the `ReadableStream` API, rendering tokens as they arrive.
- **Document parsing** — pdf.js, mammoth.js, and Tesseract.js are all client-side libraries that run entirely inside the browser's JavaScript engine.

The only network requirement is loading the CDN libraries on first use and communicating with the local Ollama API.

## Prerequisites

Complete the following setup before opening the application.

### 1. Install Ollama

Download and install Ollama from:

```
https://ollama.com/download
```

Available for macOS, Linux, and Windows.

### 2. Pull the Embedding Model

```bash
ollama pull nomic-embed-text
```

### 3. Pull an LLM

```bash
ollama pull llama3        # recommended
ollama pull mistral
ollama pull gemma2
ollama pull phi3          # lightweight option
```

### 4. Start Ollama with CORS Enabled

**macOS / Linux:**
```bash
OLLAMA_ORIGINS=* ollama serve
```

**Windows (PowerShell):**
```powershell
$env:OLLAMA_ORIGINS="*"; ollama serve
```

**Windows (Command Prompt):**
```cmd
set OLLAMA_ORIGINS=* && ollama serve
```

## Step-by-Step Setup Guide

**Step 1** — Install Ollama from `https://ollama.com/download`.

**Step 2** — Open a terminal and run:
```bash
ollama pull nomic-embed-text
```

**Step 3** — Pull your preferred LLM:
```bash
ollama pull llama3
```

**Step 4** — Start Ollama with CORS enabled and leave this terminal open:
```bash
OLLAMA_ORIGINS=* ollama serve
```

**Step 5** — Open `index.html` in your browser by double-clicking the file.

**Step 6** — Check the top-right status indicator. A green dot confirms **Ollama Connected**. The model dropdown will auto-populate with your installed models.

**Step 7** — Upload a document using the left panel. Click or drag a file onto the upload area. Watch the progress bar as the document is chunked and embedded.

**Step 8** — Once status shows **✓ Ready**, type your question in the chat input and press **Enter**.

## Using the Application

### Uploading Documents

- Click the dashed upload area or drag files directly onto it
- Multiple files can be uploaded simultaneously
- Each document shows a status badge: **Processing**, **✓ Ready**, or **✗ Error**
- A progress bar tracks embedding progress chunk by chunk
- Documents can be removed individually using the ✕ button

### Asking Questions

- Type your question in the chat input at the bottom right
- Press **Enter** to send, or **Shift+Enter** for a new line
- The AI streams its response token by token
- Source citations appear below each answer showing which document was referenced
- Chat maintains context across multiple messages (up to 20 turns)

### Controls

| Control | Location | Description |
|---|---|---|
| **Top-K** | Top bar | Number of chunks retrieved per query (default: 4) |
| **Model** | Top bar | Select which locally installed Ollama model to use |
| **Clear** | Chat input area | Clears chat history and resets the conversation |
| **✕** | Document list | Removes a document and its embeddings from memory |

## Configuration

To adjust core RAG parameters, open `app.js` and edit the values at the top:

```javascript
const OLLAMA_BASE   = 'http://localhost:11434'; // Ollama API base URL
const CHUNK_SIZE    = 500;                      // Words per chunk
const CHUNK_OVERLAP = 80;                       // Word overlap between chunks
const EMBED_MODEL   = 'nomic-embed-text';       // Embedding model name
```

Larger `CHUNK_SIZE` preserves more context per chunk but may reduce retrieval precision. Larger `CHUNK_OVERLAP` reduces information loss at chunk boundaries.

## Troubleshooting

**Status shows "Ollama Offline"**
Ensure Ollama is running with `OLLAMA_ORIGINS=* ollama serve`. Verify it is accessible by opening `http://localhost:11434/api/tags` in your browser.

**Embedding failed error**
The `nomic-embed-text` model has not been pulled. Run `ollama pull nomic-embed-text`.

**No models in the dropdown**
No LLM is installed. Run `ollama pull llama3` to install one.

**Image text not extracting**
Tesseract.js works best with high-contrast, clearly printed text. Handwritten or low-resolution images may produce poor results.

**Answer quality is poor**
Increase Top-K to retrieve more context chunks. Ensure the document status shows **✓ Ready** before querying.

**CORS errors in browser console**
Ollama was not started with the CORS flag. Stop Ollama and restart with `OLLAMA_ORIGINS=* ollama serve`.
